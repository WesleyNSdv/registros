① APIs RESTful: Integrar o sistema a serviços externos

Serviço externo: Funcionalidade pronta de outra empresa usada pela internet. (Ex: envio de SMS, mapa, trânsito) => não precisa programar do zero.

Documentação da API: Manual do serviço. Mostra endpoints, parâmetros, formato JSON, autenticação e erros. Ideia-chave: ler antes de programar.

Endpoint: URL que executa uma ação específica da API. (Ex: POST /v1/sms envia uma mensagem)

Requisição: Pedido à API = método + endpoint + headers (chave, tipo de conteúdo) + body (dados em JSON).

Código de status: Número que diz o resultado da resposta. 2xx = sucesso, 4xx = erro do cliente, 5xx = erro do servidor.

Chave de API: Código único que identifica quem chama a API. Simples de usar, boa para aplicações menores. Nunca publicar no GitHub.

OAuth 2.0: Autorização por tokens temporários que o usuário aprova. Mais seguro que a chave quando há dados de usuários.

② Docker e Kubernetes: Empacotar e entregar a aplicação sem parar

Container: Pacote isolado com a aplicação + todas as dependências. Roda igual em qualquer máquina.

Imagem: Molde somente leitura usado para criar containers. Ideia-chave: container = imagem em execução.

Docker: Plataforma que cria imagens e roda containers => ambiente padronizado e portátil.

Kubernetes (K8s): Orquestrador: gerencia muitos containers em um cluster (conjunto de servidores) de forma automática.

Réplicas: Várias cópias da mesma aplicação rodando juntas para dividir a carga e aguentar falhas.

Rolling update: Atualiza a versão aos poucos, container por container, sem deixar o sistema fora do ar.

Autorrecuperação: O Kubernetes vigia os containers e reinicia sozinho os que falham.

PV / PVC: PV (Persistent Volume) = disco do cluster; PVC (Claim) = pedido da aplicação para usar esse disco. Guarda dados que não podem sumir.

③ Pré-processadores CSS: Escrever CSS mais organizado e reutilizável

Pré-processador CSS: Linguagem que estende o CSS (variáveis, mixins, aninhamento) e é compilada para CSS puro. (Ex: Sass e Less) Ideia-chave: o navegador só lê o .css.

Variáveis: Guardam valores repetidos, como cores e espaçamentos. Sass usa $ ($primary-color: #3498db;), Less usa @ (@spacing: 16px;). Muda em um lugar => muda no projeto todo.

Aninhamento: Seletores um dentro do outro, seguindo o HTML: nav { ul { li { } } }. O & aponta para o próprio seletor. (Ex: &:hover)

Mixins e reaproveitamento: Bloco de estilos reutilizável. Sass: @mixin rounded($radius) + @include. Less: chamar a classe base, .primary-button { .button; }.

Funções de cor: Sass: color.adjust($cor, $lightness: 10%) muda a luminosidade (darken() está descontinuado). Less: fade(#3498db, 50%) muda a opacidade.

Instalar e compilar: Com Node.js: npm install -g sass e npm install -g less. Compilar: sass sass/style.scss css/style.css ou lessc less/style.less css/style.css => o HTML liga o style.css.

④ Otimização de carregamento: Deixar o site mais leve e mais rápido

Lazy loading: Carrega imagens, vídeos e iframes só quando vão aparecer na tela, e não tudo ao abrir a página.

loading="lazy": Atributo do HTML que ativa o lazy loading sem JavaScript. (Ex: <img src="foto.jpg" loading="lazy">)

Onde usar lazy loading: Imagens, vídeos e iframes abaixo da dobra. Não usar no conteúdo do topo nem em scripts essenciais.

Otimização de CSS: Minificar e remover regras não usadas => arquivo .min.css menor para produção.

WebP: Formato de imagem do Google, mais leve que JPEG e PNG com qualidade parecida.

Compressão com / sem perda: Lossy = arquivo bem menor, perde um pouco de qualidade. Lossless = mantém a qualidade, reduz menos.

Imagens responsivas: Entregar um tamanho de imagem para cada tela => o celular não baixa foto gigante.

SEO: Otimização para buscadores. Site mais rápido tende a aparecer melhor no Google.

⑤ Webpack: Empacotar módulos e dependências do front-end

Módulo: Arquivo de código que importa e exporta partes de outros (import / export). Organiza o projeto.

Webpack (module bundler): Lê os módulos a partir da entrada, segue os imports e gera um pacote final (bundle).

Bundle: Arquivo final gerado pelo Webpack. (Ex: dist/main.js) => menos requisições HTTP.

webpack.config.js: Arquivo de configuração do Webpack, na raiz do projeto.

entry / output: entry = arquivo de onde o Webpack começa (src/index.js); output = nome e pasta do bundle (dist/main.js).

Loaders: Ensinam o Webpack a processar arquivos que não são JS. css-loader lê o CSS; style-loader injeta o CSS na página.

mode: development = código legível e build rápido; production = minifica e otimiza automaticamente.

npm run build: Comando que roda o Webpack (script "build": "webpack" no package.json) e gera a pasta dist.

⑥ Firebase e Google Maps: Usar back-end e mapas prontos no front-end

Firebase: Plataforma do Google com back-end pronto: autenticação, banco de dados e hospedagem. BaaS (Backend as a Service).

Firebase Authentication: Faz registro, login e logout por e-mail/senha ou por Google, Facebook etc.

Realtime Database: Banco NoSQL em nuvem que guarda JSON e sincroniza em tempo real com todos os usuários.

Rota protegida: Página que só abre para usuário logado. Sem login => volta para a tela de login.

Maps JavaScript API: API do Google que desenha mapas interativos no navegador. 1º passo: habilitar no Google Cloud Console.

google.maps.Map: Cria o mapa dentro de uma div. Precisa de center (latitude e longitude) e zoom.

Marcador (Marker): Alfinete que indica um local. Precisa de position (coordenadas) e map (em qual mapa).

addListener: Liga um evento a um elemento do mapa. (Ex: clique no marcador abre um balão InfoWindow)

⑦ DevSecOps: Colocar segurança em todo o ciclo e tratar erros direito

DevSecOps: Desenvolvimento + Segurança + Operações. Segurança em todas as fases, como responsabilidade de todos.

DevOps x DevSecOps: DevOps une dev e operações para entregar rápido; DevSecOps acrescenta segurança desde o início.

SAST: Teste de segurança estático: analisa o código-fonte sem executar. (Ex: achar senha escrita no código)

DAST: Teste de segurança dinâmico: ataca a aplicação rodando, como um invasor faria.

Detecção precoce: Achar a vulnerabilidade no começo do desenvolvimento => corrigir custa menos e o risco cai.

Exceção: Sinal de erro que interrompe o fluxo e é tratado com try/catch. Separa erro da lógica principal.

Exceção específica: Criar um erro com nome próprio (Ex: SaldoInsuficienteError) em vez de capturar erro genérico.

Não retornar null: Retornar null causa erro de referência nula. Usar exceção ou objeto vazio.
