① APIs de terceiros: Integrar o back-end com serviços externos

Ferramentas de integração: Bibliotecas, frameworks ou middleware que facilitam a comunicação entre sistemas diferentes.

Cliente HTTP: Biblioteca que padroniza as chamadas a APIs REST. (Ex: Axios no Node.js, Retrofit no Java)

Endpoint: Endereço (URL) da API que recebe um tipo de requisição. (Ex: GET /clima?cidade=SP)

Código de status: Número que a API devolve dizendo o resultado => 200 (ok), 401 (não autenticado), 404 (não encontrado), 500 (erro no servidor).

API Key (Chave de API): Chave simples que identifica quem chama o serviço. Fácil de usar, mas menos robusta.

OAuth 2.0: Dá acesso limitado a um serviço sem expor a senha do usuário (Ex: "Entrar com Google").

Tratamento de respostas: Fazer o parsing do JSON, conferir o código HTTP e tratar os erros com try/catch.

Variável de ambiente: Lugar fora do código para guardar chaves e tokens. Ideia-chave: segredo nunca vai para o Git.

② Jenkins: Automatizar build, testes e entrega

CI (Integração contínua): Valida o código automaticamente a cada commit, com build e testes.

CD (Entrega/Deploy contínuo): Publica automaticamente em produção as versões que passaram na CI.

Jenkins: Servidor de automação que executa a pipeline de CI/CD.

Pipeline: Fluxo automatizado em etapas => Build → Test → Package → Deploy.

Jenkinsfile: Pipeline escrita como código e versionada junto com o projeto.

Testes automatizados: Scripts que testam o sistema sozinhos a cada mudança. (Ex: JUnit, Selenium)

Staging: Ambiente de validação, igual à produção, usado antes de publicar.

Rollback: Voltar para a última versão estável quando uma nova versão ou atualização falha.

③ Servidor seguro: Proteger o servidor web contra ataques

TLS: Protocolo que cifra e autentica a conexão entre cliente e servidor.

HTTPS: HTTP com criptografia TLS; protege os dados entre o cliente e o servidor.

Certificado digital: Comprova a identidade do site e habilita o HTTPS (cadeado no navegador).

Redirecionamento: Envia todo acesso HTTP (porta 80) para HTTPS (porta 443). (Ex: redirect 301 no Nginx)

Firewall: Filtra o tráfego e permite ou bloqueia conexões por regras.

Regra de ouro do firewall: Liberar só os serviços essenciais e revisar as regras com frequência.

Superfície de ataque: Tudo o que fica exposto e pode ser atacado (portas, serviços, contas).

Hardening: Práticas que diminuem a superfície de ataque => atualizar, remover serviços desnecessários e usar senhas fortes.

④ JWT: Autenticar o usuário na API com tokens

JWT (JSON Web Token): Token assinado digitalmente, em formato JSON, que identifica o usuário sem guardar sessão (stateless).

Estrutura do JWT: Três partes separadas por ponto => header.payload.signature.

Header: Diz o tipo do token e o algoritmo de assinatura. (Ex: HS256, RS256)

Payload: Guarda as claims, isto é, os dados do usuário (sub, role, exp). É só codificado: nada de senha nele!

Signature: Assinatura feita com a chave secreta; garante que o token não foi alterado.

Fases do JWT: Geração no login → envio no header Authorization: Bearer <token> → validação na API.

401 x 403: 401 Unauthorized = sem token ou não autenticado; 403 Forbidden = sem permissão (ou token recusado).

Boas práticas do JWT: Expiração curta (exp), chave em variável de ambiente, refresh token e blacklist.

⑤ Patches: Manter o servidor atualizado e seguro

Vulnerabilidade: Falha no software que pode ser explorada por um ataque.

Patch: Correção pontual de uma falha de segurança no software.

CVE: Código público que identifica uma vulnerabilidade conhecida. (Ex: Log4Shell)

Servidor desatualizado: Fica exposto a vulnerabilidades que já são conhecidas pelos atacantes.

Homologação: Ambiente de teste onde o patch é aplicado antes de ir para a produção.

Validação: Testes e auditorias de segurança depois de aplicar o patch.

Monitoramento de segurança: Acompanhar boletins de segurança, scanners e logs para saber quando atualizar.

⑥ Spring Boot: Criar uma API REST em Java

Spring Boot: Framework Java que simplifica o back-end com configurações prontas e servidor embutido.

Spring Initializr: Site que gera o projeto já configurado, com as dependências escolhidas.

Dependências: Bibliotecas adicionadas ao projeto => Spring Web (API), Spring Data JPA (banco) e H2 (banco em memória).

mvn spring-boot:run: Executa o projeto com o Tomcat embutido, por padrão na porta 8080.

Anotações do controlador: @RestController (classe da API), @RequestMapping (rota), @PostMapping (POST) e @RequestBody (JSON recebido).

JPA: Mapeia classes Java em tabelas do banco; cada classe com @Entity vira uma tabela.

Repositório: Interface que estende JpaRepository e faz o CRUD sem escrever SQL. (Ex: repository.save(obj))

⑦ Monitoramento de APIs: Acompanhar a API em produção

Monitoramento de API: Acompanhar a API em produção para garantir disponibilidade, desempenho e confiabilidade.

Métricas da API: Latência, requisições por minuto e taxa de erros 5xx (erros do servidor).

Prometheus e Grafana: Prometheus coleta e guarda as métricas; Grafana mostra em dashboards (painéis com gráficos).

Alerta: Aviso automático para a equipe quando uma métrica passa do limite.

Threshold (limiar): Valor-limite que precisa durar um tempo antes de alertar => evita falso positivo (alerta sem problema real). (Ex: erros 5xx > 5% por 5 min)

Severidade: Nível de gravidade do alerta => crítico, alerta e aviso.

Log: Registro, com data e hora, do que acontece na aplicação; é o raio-x dela. Métricas mostram que algo está errado; logs mostram o porquê. (Ex: ELK Stack, Graylog)

Tipos de logs: Acesso (quem chamou o quê), erro (falhas) e auditoria (quem fez o quê).
