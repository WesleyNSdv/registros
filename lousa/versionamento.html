① Git Workflows: Organizar o trabalho da equipe com branches

Commit: Registra uma mudança no histórico do projeto, com mensagem explicando o que foi feito.

Branch e merge: Branch é uma linha separada de trabalho; merge junta uma branch na outra (ex: na main).

Feature Branch Workflow: Uma branch para cada funcionalidade; quando fica pronta, faz merge na main.

Integração tardia: Branch que fica muito tempo separada => mais conflitos e erros descobertos tarde.

Entrega contínua: Mudanças pequenas e frequentes, fáceis de validar e de publicar.

GitFlow: Usa as branches main, develop, feature, release e hotfix => mais controle, porém mais complexo.

Trunk-Based Development: Integrações pequenas e frequentes direto na branch principal (trunk). Funciona melhor com testes automatizados.

Escolha do workflow: Depende do tamanho da equipe, do controle necessário e da frequência de entrega.

② Pull Request: Revisar o código antes de juntar na main

PR (Pull Request): Pedido para juntar as mudanças de uma branch ao código principal do projeto.

PR é comunicação: Mostra o que mudou e por que mudou, e abre espaço para a revisão da equipe.

Bom PR: Título claro e descrição objetiva com problema, solução e impacto. (Ex: "Corrige falha no login com senha longa")

Code review: Colegas avaliam o código quanto a clareza, lógica, riscos e testes.

Checklist de revisão: O código funciona? Os nomes são claros? Os testes passaram? A descrição está completa?

Aprovação: Regra com número mínimo de revisores que precisam aprovar antes do merge.

Checagens automáticas: Testes automatizados e análise de qualidade que rodam sozinhos em cada PR.

Branch protegida: A main só recebe PR revisado, aprovado e com as checagens passando.

③ Monorepo x Polyrepo: Decidir como guardar vários projetos

Monorepo: Vários projetos guardados em um único repositório Git.

Polyrepo: Um repositório separado para cada projeto => mais independência, mas mudanças coordenadas ficam difíceis.

Problemas de muitos repositórios: Dependências difíceis de enxergar, mudanças espalhadas e padrões diferentes em cada repo.

Mudança atômica: Alterar vários projetos em um único commit, todos juntos e de uma vez.

Benefícios do monorepo: Código compartilhado, mudanças atômicas e releases (versões) coordenados.

Desafios do monorepo: Repositório grande, governança, controle de permissões e builds lentos.

Nx: Ferramenta que monta o grafo dos projetos, usa cache e roda tarefas só no que foi afetado.

Bazel: Ferramenta de build e teste em larga escala, com resultados reproduzíveis e dependências organizadas.

④ RabbitMQ: Rotear mensagens com Exchanges Direct e Topic

Exchange: Recebe a mensagem do publisher e encaminha para as filas certas.

Routing key: Chave enviada junto com a mensagem, usada para decidir o destino. (Ex: pedido.criado)

Binding: Ligação entre um exchange e uma fila, com a regra de entrega.

Direct Exchange: Roteamento exato => entrega na fila cuja chave é igual à routing key.

Topic Exchange: Roteamento por padrões, com palavras separadas por ponto e curingas.

Curinga *: Substitui exatamente uma palavra. (Ex: pedido.* aceita pedido.criado)

Curinga #: Substitui zero ou mais palavras. (Ex: pedido.# aceita pedido.pago.pix)

Várias filas: Uma mesma mensagem pode ser entregue em várias filas ao mesmo tempo.

⑤ Kafka Streams: Processar dados em tempo real

Kafka Streams: Biblioteca do Apache Kafka para processar fluxos de dados em tempo real.

Tempo real: Processa cada evento assim que ele chega, sem esperar juntar um lote.

Stream: Fluxo contínuo de eventos, como um histórico. (Ex: todas as compras realizadas)

Table: Estado atual; guarda só o valor mais recente de cada chave. (Ex: estoque atual)

Topologia: Caminho dos dados => ler → filtrar → transformar → agrupar → enviar.

DSL: API Java que facilita montar o fluxo; a forma recomendada para começar.

Estado local: Guarda valores parciais usados em agregações, contagens e joins.

ksqlDB: Permite consultar streams com comandos parecidos com SQL, de forma rápida e simples.

⑥ Observabilidade em mensageria: Acompanhar a saúde das filas

Monitorar filas: Perceber acúmulo, atraso e gargalo antes que vire falha.

records_in (Kafka): Quantidade de mensagens entrando no sistema.

consumer_lag (Kafka): Atraso entre o que foi produzido e o que já foi consumido. Lag crescendo => consumidor lento.

queue_depth (RabbitMQ): Quantidade de mensagens esperando na fila.

Prometheus: Coleta métricas do endpoint /metrics e permite montar dashboards e alertas (ex: no Grafana).

Log estruturado: Log com campos organizados e padronizados (ex: JSON), fácil de filtrar e pesquisar.

OpenTelemetry: Padrão que conecta métricas, logs e tracing distribuído (o caminho de uma mensagem entre serviços).

Métrica x log/trace: A métrica mostra o que está acontecendo; log e trace mostram a causa.
